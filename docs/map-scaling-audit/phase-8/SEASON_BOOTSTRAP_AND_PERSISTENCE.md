# Season bootstrap and persistence

The development-only bootstrap created a future season identity, loaded the 25-cell permanent Core template, confirmed zero Core spawn-eligible cells, verified all four Holding Tower reservations, initialized 25 seasonal objective records, established Layer 1 slot 0, prepared two STANDBY regions, activated one initial capacity region, simulated placements, and replenished the buffer to two.

No reset or production write occurred. Approved Phase 6F raster records were not relabeled under the future season identity: changing world/season identity changes deterministic seeds, so future-season packages must be freshly generated and published under their own immutable identity.

Future reset persistence remains:

- player flag and customization
- persistent Clan identity and membership
- Common Gear ownership
- equipped Common Gear
- Common Gear levels, upgrades, and progression

Seasonal cities/ownership, objectives, marches/armies, region activation, and normal consumables reset according to the existing contract. Phase 8 changes no live persistence behavior.
