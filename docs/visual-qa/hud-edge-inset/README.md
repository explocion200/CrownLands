# HUD left edge inset — draft

Branch: `codex/hud-left-edge-inset-draft`. Base: `9f08953e420c60af6a96bab36e32c2ee199c0f75`. Awaiting design approval; no production files or gameplay behavior changed.

Move the already-aligned player row and Gold to the same 12px left inset as Reports on desktop and mobile landscape. This supersedes the initial draft using the gaps between top buttons. Preserve artwork, dimensions, vertical placement and all gaps within the block. The profile's compact combat timers move with their parent; Reports and other HUD controls stay put.

The existing layout runtime sets `.profile-stack` to `left:12px` inside `.top-hud`, which already has its own `max(.75rem,env(safe-area-inset-left))` inset. The player row and Gold each have a -7px margin, yielding the current 17px outer inset when the safe area is zero. The draft changes only the stack's local left offset to 7px, cancelling those margins and producing the 12px outer edge. A scoped CSS override stays effective when the layout runtime refreshes on resize. The header's existing safe-area inset takes priority if a device notch requires more than 12px; Reports positioning is not changed by this draft. No production layout/configuration changes are included yet.

Run the local benchmark server on 61704 and open `/docs/visual-qa/hud-edge-inset/index.html?viewport=landscape`. Desktop, mobile landscape and small landscape use native CSS sizes, with Current game / Match Reports and an optional guide extending down to Reports. The preview uses synthetic data and intercepts navigation; it never connects a real player account. The guide is not part of the proposed game UI.

Focused browser validation covers 1440×900, 844×390 and 568×320. Row and Gold move from 17px to 12px, matching the actual Reports button edge, with unchanged control dimensions/colors/vertical positions, working hit targets and no movement of the other checked HUD controls. Geometry remains unchanged at 220% map zoom. A simulated 44px header safe area keeps the top controls inside that protected edge after a layout refresh. Before/after, viewport and guide controls are checked; evidence is in ignored `release-artifacts/hud-edge-inset/`. This is browser and simulated safe-area verification, not physical-device testing.
