# Tiny City Estate review

This development-only page mounts the production renderer with three fixtures: six completed buildings and fourteen surveyed plots, all twenty completed buildings, and all twenty construction sites. It cannot spend resources, start construction, change saved progression or dispatch champions. Production excludes this page and its controls.

Run `node tools/map-benchmark/server.js --port=8816` from the feature checkout and open `http://127.0.0.1:8816/docs/visual-qa/inner-city-estate/index.html?scene=completed&estateUi=1&revision=r6`. This route uses the real game and equipment screens with the existing loopback-only synthetic backend. Click a completed Treasury, Barracks, Gatehouse or Royal Stables through its map target or directory entry to open equipment directly; Back restores the camera, selection, focus and development fixture. No dotted plot-selection boundaries cover the art. The bottom-right selector switches scenes; construction sites only show their site description. Omit `estateUi=1` for the standalone artwork fixture, which has a **Building UIs** link to the interactive preview. Production excludes both the fixtures and this runtime.

Pan, pinch/wheel zoom, Fit Estate, districts and the twenty-building directory use the production implementation. The logical map is 1448 × 1086, matching both the active topology's catalog and an actual illustrated regional asset. Full, Reduced and Off display the still estate; ambient motion is deferred.

`node tools/validate-inner-castle-browser.js` exercises all twenty selections at 1440×900, 844×390 and 568×320, direct gear entry from directory and actual map clicks/touch taps, keyboard entry, twenty-four camera/focus-preserving gear round trips, absent dotted boundaries, nonoverlapping 44px targets, mouse drag, wheel/touch pinch, keyboard camera controls, zoom bounds, animation preferences, background visibility, city/Profile entry and modal cleanup. It also checks the real-UI preview's four officer screens, construction guards, centered freestanding art without soil overlays, Gatehouse target alignment, native sprite density and visible lazy detail tiles. Screenshots go to ignored `release-artifacts/inner-city-estate/`, including `fixture-completed.png`, `gatehouse-zoom-4x.png`, `city-zoom-4x.png` and the four `gear-*.png` officer screens.

It reads the active catalog and an actual map WebP to verify dimensions. `node tools/validate-inner-castle.js` and `node tools/validate-common-gear.js` retain access, original preview artwork and authoritative gear checks. Production artifact validation verifies inclusion of all 27 estate images, bounded lazy close-ups and unchanged installation/login budgets.

Review the buildings on their integrated terrain ground in all three states, the Gatehouse foundation against both wall ends, common building scale and miniature silhouettes. There should be no repeated independent soil islands or spare work-yard clearings beside completed structures. At 4×, inspect roof timbers, masonry, outlines, terrain detail and tile seams. The world must rerasterize at the selected zoom rather than reuse an overview-resolution composited bitmap. Terrain, masonry and decorative cottages remain painted; site-state artwork changes independently within fixed reservations. Automated entrance checks apply to the layout graph; painted paths and junctions also require visual review.
