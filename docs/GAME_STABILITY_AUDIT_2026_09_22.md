Sustained production load remains the test of memory headroom. |

## Feature coverage

The user's explicit full-test request invokes the full release regression, beyond the normal affected-test policy. The suite covers authentication/session replacement and realm admission; first-time claims and Main City recovery; economy, city/wall upgrades and concurrent/idempotent spending; ordinary/bulk marches, scouting, combat, shields and retaliation; Camps, Strongholds and Citadel; clans, Rallies, Towers, Treasury and buildings; Shop, Bag, gear, skills and presets; daily rewards, missions, achievements and rankings; chat/translation, activity and reports; generation/reset isolation and Firestore rules; maps, gestures, modal lifecycles, responsive HUD, audio, service workers and release artifacts. The committed validation plan also names the directly affected regression files.

Performance checks use isolated simulated services and measure map startup, idle marches, pan, zoom, dialogs, map switching, listener cleanup, browser exceptions, resource failures and heap across desktop, landscape mobile and 4× CPU profiles. A separate lifecycle soak exercises map switches, foreground transitions and reconnects. Raw reports remain in `release-artifacts/stability-audit/` and the completion report records results. Performance samples from different durations or traffic windows are not presented as a measured production speedup.

The bounded production log baseline queries a 24-hour window but reaches the 1,000-entry page limit. Its error sample includes repeated army-resolution log entries, not a count of affected players or distinct requests. The HTTP sample mixes different functions and preflights and therefore does not establish a game-wide latency percentile. Logs are reduced to operational summaries; identities, payloads, tokens and private game state are not retained in the report.

A second query excluding the two dominant failing services returned 97 error entries without truncation. In addition to the mission-worker memory failures, it found translation 503s and army/economy timeouts on older revisions. Those failures predate the currently deployed September 22 revisions; the current Translation API is enabled and the runtime account has its translation role. They are recorded as historical symptoms and checked again after release, rather than attributed to an unproven new root cause.

The first 15-case map matrix completed 14 profiles with no uncaught browser exceptions, failed requests, duplicate listeners or production-backend calls. The heavy 150-city/100-march case at 4× CPU slowdown exceeded its 180-second watchdog. Normal desktop/mobile-emulation profiles passed the existing frame-rate capacity checks, but total DOM, request counts and estimated decoded images exceeded the older resource budgets; those budgets were not relaxed to manufacture a pass. The extreme CPU cases remain a capacity risk, not evidence that all devices are smooth.

A focused 10-second, 100-city/50-march instrumented comparison at the same 4× CPU setting measured 10.3 → 22.9 idle FPS and 54.3 → 32.2 ms per march-render pass after the label/attribute correction. Troop-label work fell from 1,140 ms to 62 ms across the sample. This is a local diagnostic comparison, not a production or physical-phone speed guarantee. Final matrix, lifecycle soak, full CI and publication receipts are recorded in the release handoff.

## Limits and release checks

Full regression also exposed stale test assumptions: the audio fixture lacked the worker background-task API, the report autosave fixture lacked its signed-in UID, and the army validator expected the pre-migration CI command. Rally and onboarding fixtures now exercise current modal ownership, verified-profile admission and the dedicated identity-write API, including failed-write draft retention and blocked projections. These fixture repairs do not relax runtime guards. The offline-shell byte allowance was last updated at `90b8f2e`; intervening approved Tower, identity and fullscreen work added 49,907 normalized bytes before this audit, which adds 1,385 bytes. A bounded 52 KiB allowance records that 51,292-byte source increase while preserving all offline dependencies. This adjustment does not change the map runtime budgets or turn their resource failures into passes.

Automated tests do not prove every possible game state or device. Actual OS notification display, delivery to a sleeping phone, browser permission prompts, native fullscreen/rotation and existing PWA manifest updates need physical-device checks. Production player actions are not used as destructive test fixtures. Firebase Messaging and Firestore cannot share a transaction: a crash after external delivery but before recording success can still cause an at-least-once retry; the stable notification tag helps consolidate display.

No new mechanic is inferred for the explicitly deferred Tower Veil purchase/inventory design. Its current activation behavior and documented pending design remain unchanged. Deployment alone does not repair expired history or authorize world resets.

Release verification must check the deployed backend source, web and itch build fingerprints, public startup/reload, service worker and fullscreen controls, then inspect fresh operational logs. Older native fullscreen installations may require reopening after their browser applies the manifest update, or reinstalling from `https://playcrownlands.com/play/` without clearing website data.
